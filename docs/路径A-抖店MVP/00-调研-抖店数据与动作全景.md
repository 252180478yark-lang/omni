## 一、数据来源 1：抖店罗盘

> **路径**：https://compass.jinritemai.com/
>
> **状态**：✅ 已完成（基于 83 张截图取证 + 老板高频操作路径推断）
>
> **本店类目**：调味品 / 干货 / 方便速食（一级类目"粮油干货/方便速食"）
>
> **典型操作时间窗**：晚 22:00–24:00 复盘当天经营。

### 1.0 调研结论摘要（先读这一节就够）

1. **罗盘的核心定位是"诊断 + 排名 + 复盘"**，不是"实时下钻看明细"。明细要去抖店后台 / 千川后台。
2. **13 个一级菜单**几乎覆盖所有店铺侧可见数据（除付费投放细颗粒度归千川）。但**实际每天高频看的只有 4–5 个**：首页 / 交易 / 商品 / 体验，加上有直播日加上"直播"。
3. **数据更新口径几乎都是 T+1**（次日刷新昨日全量）。**少数页面支持"近 1 天"实时**（首页大盘 / 直播实时 / 大促作战室）。
4. **导出能力普遍存在**（页面右上角"下载明细"），多数为 Excel/CSV，时间维度可选近 1/7/30 天 / 自然日 / 自然月 / 大促。
5. **关键字段口径必须以"用户支付金额（GMV）"为主线**——退款率 / 客单价 / UV 价值都围绕它。**不要混用"成交金额"和"用户支付金额"**（前者含未支付订单，后者才是实付）。
6. **行业对比 = 罗盘的杀手锏**——"行业均值"、"优于同行 X% 商家"几乎每个核心指标都有，**老板做异动判断时最依赖这个比较视角**。
7. **罗盘自带"机会/榜单"**（市场→机会赛道、各类 TOP200 榜单），是**爬竞品和找选品方向的首选**，比第三方飞瓜/蝉妈妈更权威，**MVP 应优先抓罗盘的榜单而非第三方**。

### 1.2 各模块详细数据

#### 1.2.1 首页（home）

**路径**：罗盘首页 https://compass.jinritemai.com/shop/home

**页面包含**：
- **大盘卡片**：用户支付金额、支付订单数、GMV、UV、UV 价值（共 5 张）
- **类目均值对比**：本店 vs 行业均值 / 优秀均值（如 17.92% / 22.72%）
- **昨日成交趋势**：折线（含本周对比）
- **GMV 来源结构**：直播 / 短视频 / 商品卡 / 搜索 / 达人（环形或堆叠）
- **异动提醒**（页面顶部黄色横条）：如"昨日成交 + 32% / 退款率突增"

**频率**：T+1（22:00 后看昨天最稳）；含"近 1 天"实时口径（不全）。
**导出**：右上角"下载明细"。
**筛选**：时间维度（近 1/7/30 天 / 自然日 / 自然周 / 自然月 / 大促）；可对比"上一周期 / 去年同期"。

**导出**：列表支持下载明细。

### 1.5 此次调研的重要发现（影响 MVP 设计）

1. **罗盘已经把"竞品对比 / 榜单 / 类目机会 / 用户原声 / 商家体验分"五件大事打包**——这意味着 MVP 抓取范围**应集中在罗盘**，而不是去爬第三方（飞瓜/蝉妈妈）。第三方留给 v2 做交叉校验。
2. **"用户支付金额"是绝对主线指标**——不是 GMV、不是成交金额。所有 runbook、所有日报、所有 SKU 卡片都用这个口径。
3. **"行业均值/优秀均值"是判断异常的天然门槛**——MVP 应把每条指标都附带"行业均值 / 行业百分位"作为基线，而不是只看本店环比。
4. **"商品详情"页（product-detail）的 7 Tab 结构正好对应我们设计的 omni SKU 详情 7 Tab**——结构可直接照抄（源分析 / 流量分析 / 流量人群 / 内容分析 / 商品卡分析 / 售后分析 / 人群分析）。
5. **"用户偏好-机会总结"** 给出了"本店用户在友商买了什么我没卖"——这个信号比任何选品工具都直接，**MVP 必抓**。
6. **客服分析的"咨询意图分组"**（按商品 + 按意图）是**最直接的产品改进 / FAQ 优化信号**——MVP 应每天抓 TOP 5 咨询意图。
7. **罗盘没有付费投放细颗粒度**（只有"渠道占比"层级的"投流"切片），**千川的实际投放数据要去千川后台抓**——这意味着路径 A 必须包含千川 runbook（不能只抓罗盘）。
8. **罗盘的"营销工具分析"颗粒度有限**——满减/券/拼团的真实使用率仍要去抖店后台抓，MVP 第二阶段考虑。
9. **"达人推荐"页（talent-prefer-live）是平台主动推送的合作机会**——可定时抓变化，对寻找新达人合作很有价值。

### 2.0 调研结论摘要（先读这一节就够）

1. **抖店后台和罗盘的角色严格分工**：罗盘 = "看 + 诊断 + 排名"；抖店后台 = "做动作 + 管订单 + 处理售后"。两者数据有一部分重叠（首页有体验分 / 流量/订单概览），但**罗盘是分析视角，抖店后台是执行视角**。
2. **抖店后台是"动作发生地"**：上下架、改价、报活动、回复客服、发货、客服补偿、退款审批、库存调整、千川推广跳转——**所有 §12 动作都从这里发起**。
3. **MVP 应当从抖店后台抓"动作日志"，从罗盘抓"指标日报"**——前者反推 `change_event`，后者反推 `daily_metric`。这是关键的取舍。
4. **9 个一级菜单**：常用 / 流量 / 订单发货 / 售后 / 商品 / 店铺 / 用户 / 资金 / 应用，加上 AI 助手入口。
5. **顶部恒定全局入口**（5 个跳转）：巨量千川 / 精选联盟 / 电商罗盘 / 服务市场 / 学习中心。这表明罗盘在抖店生态里就是"嵌在抖店后台旁边的姐妹站"。
6. **物流诊断子页**含"超时单分析 / 揽收时长（5.70 时） / 合作物流商分析"——比罗盘更细，**物流相关 runbook 应抓抖店后台 logistics-project-diagnosis-index**。
7. **评价管理（评价概览）**有"评价数 / 优质评价占比 / 差评率 / 实拍评价"等更细字段，**比罗盘"用户原声"多一层"实拍占比 / 邀请评价"维度**——MVP 应交叉抓。
8. **会员/用户中心**（mvip-consumer）有"用户总成交金额 / 会员复购金额 / 用户分群标签"——为路径 A 后期"私域召回"动作提供弹药。
9. **商品列表（g-list）含"618 报名"等大促入口** + 商品状态/库存/SKU ID，**MVP 抓 SKU 主数据应来自这里**（不是罗盘的 commodity-product-list，那是"看版"，不是"管版"）。

### 2.6 此次调研的重要发现（影响 MVP 设计）

1. **抖店后台 = 动作日志金矿**——所有 §12 动作都在这里发起，且**多数有原生历史/记录页**（库存变更记录、活动报名记录、发布历史、触达历史）。**MVP 让用户"60 秒登记"以外，还可以从抖店后台被动抓动作日志**——双轨并行，提高完整度。
2. **物流诊断 > 罗盘物流** —— 物流相关 runbook 数据源应改为抖店后台（合作物流商 / 揽收时长 / 超时单按发货地分布），罗盘只给 3 个粗指标。
3. **评价管理含"实拍 / 邀请 / 视频"工具维度**——这是罗盘没有的，**优质评价占比和实拍占比是 SKU 内容质量的代理指标**。
4. **SKU 主数据要从抖店后台抓**（g-list）——罗盘的 commodity-product-list 是衍生视图，SKU ID 本源在抖店后台。施工时数据库 `mvp_sku.source = 'shop_admin'`。
5. **首页 6 待办数字是绝佳的"风险信号"**——MVP 每天抓一次首页待办数 → 自动提醒老板"今天有 X 个售后待处理"。
6. **顶部全局条说明罗盘和抖店后台共用登录态**——爬虫策略上，**一次 cookie 登录可以同时访问 fxg + compass**，节省登录工作量。
7. **AI 助手 / 智能托管已是抖店后台官方功能**——意味着平台已经在做"AI 托管"方向；omni-vibe 不能停留在"看板"层面，必须在 v2 进入"行动建议 + 一键执行"才能差异化（但路径 A 共识 #8：AI 不自动执行）。

### 3.6 此次调研的重要发现（影响 MVP 设计）

1. **5A 资产模型是 MVP 不能省的视角**——罗盘 / 抖店后台都不给"未购买的潜在人群"信息，云图给。**没有 5A 就没有"今天该做什么动作"的判断**。
2. **6 场景流转 = 6 类决策建议**——直接驱动 omni-vibe 的"今日建议"模块（路径 A 共识 #8 "AI 不自动执行，只给建议"）。
3. **品牌心智 3 指标（联想量/美誉度/偏爱度）补全了"非交易"层面的健康度**——这对调味品老板尤其重要（口碑型生意）。

5. **行业排名是云图独有的 benchmark**（如"行业排名 1732 ▼ 35"）——比罗盘的"优于同行 X%"更直观，**MVP 应当把"行业排名"作为每个核心指标的标配字段**。
6. **云图自带 AI 总结**（如 5A 资产卡的 "你的品牌人群资产规模，近 30 天以来，环比上升 36.99%，**高于对比品牌均值，建议持续关注**"）——这种自然语言总结风格直接对标 omni-vibe 的目标。

8. **商品级 5A** 让我们能给每个 MVP SKU 单独画"5A 心电图"——比罗盘 product-detail 的 7 Tab 多了"该 SKU 的 5A 资产规模 / 流转效率"两层。

## 十二、动作类型反推（核心环节）

> **逻辑**：每个数据维度都受某些"动作"影响。穷举完数据后，反推动作类型清单。
> **MVP 列**：✅ 必登记 / 🟡 选登记 / ❌ 暂不登记
> 这个清单将直接作为路径 A `change_event.asset_type` / `change_event.action_type` 枚举的设计依据。
>
> **【关键发现 from 抖店后台调研】**：动作不仅靠用户"60 秒登记"，**多数动作在抖店后台留有原生历史/日志**——MVP 应当**双轨**：
> - **轨 A：用户登记**（极简表单，§12.11）→ 用于补全平台不记录的动作（如"今天去仓库换了快递公司")
> - **轨 B：被动抓取抖店后台动作日志**（库存变更记录 / 活动报名记录 / 评价回复操作 / 发布历史 / 售后工作台日志）→ 自动化补全
> 两轨**互相校验、互相补全**——若用户漏登记 → 抖店后台日志兜底；若动作发生在系统外（如线下会议决策）→ 用户登记兜底。

## 十三、MVP 取舍：从全景到 14 天可交付

### 13.1 数据维度优先级矩阵（价值 × 抓取难度）

```
                高价值
                  ↑
     [必抓 P0]   │   [优先抓 P1]
   GMV/UV/退款率 │   差评关键词/咨询意图/
   体验分/客单   │   引流词/用户偏好-机会总结
   付费 vs 自然  │   榜单 TOP200 / 类目机会
                  │
   ───────────────┼─────────────────→
   低难度         │   高难度
                  │
     [次要 P2]   │   [先放放 P3]
   榜单截图归档   │   云图标签深度抓取/
   达人列表       │   竞对 SKU 维度全量抓
                  ↓
                低价值
```

**抓取难度分级**：
- **低难度（P0/P2 候选）**：罗盘自带"下载明细"按钮，本地可解析 Excel/CSV → ETL 入库
- **中难度（P1 候选）**：HTML/JSON 接口需登录态，须用 Playwright + cookies 或半自动（用户每周登一次）
- **高难度（P3 候选）**：页面强依赖前端渲染 + 反爬 + 需付费开通"数据工厂" API

### 13.3 MVP 应该让用户登记的动作类型（双轨策略）

> 详细字段定义见 §12.11。
>
> **双轨**：用户主动登记（轨 A）+ 抖店后台被动抓取（轨 B）。✅✅ = 双轨都有；✅+ = 主登记 + 后台兜底；+✅ = 后台为主 + 用户补登

| 优先级 | 动作大类 | 必填子类型范围 | 触发场景 | 双轨 |
|---|---|---|---|---|
| **P0** | 商品类（12.1） | 上下架 / 改库存 / 组合套装 / SKU 规格 | 任何 SKU 改动 | ✅✅（库存变更记录兜底）|
