## 0. 一句话结论（2026-06-15 晚更新）
京东商智业务接口走 **`szgateway.jd.com/api/lowcode/*.ajax`**，POST JSON，统一 `{header,body,errors}` 封套，37 业务接口已摸清，登录态已存。
**⚠️ 轨 A（参数化裸 replay）走不通**：szgateway 有 **`user-mnp` 每请求签名头**（obfuscated SPA JS 算，非简单 md5），缺它返 `header.code=-402「不安全的请求」`。**不 forge 签名**（脆弱、属反爬对抗）。
**✅ 改走 passive 抓取轨**：headed 浏览器（容器 xvfb 实测过 jdsz 反爬）加载商智页 → SPA 自己签名发请求 → 我 `page.on(response)` 抓响应（已用 133MB survey HAR 证明 119 接口真数据可抓）。详见 §8。

## 6. ⚠️ 反爬（切片2 首要风险）
`jdsz/sz-online/szgateway` 对**自动化/headless 浏览器** TLS 层 `ERR_CONNECTION_CLOSED`，**只有真人驱动的真 headed 浏览器过**（老板登录那次 + headed 自动逛过了；headless 必挂）。

## 8. 轨道修正（2026-06-15 实测）：轨 A 被签名挡 → 走 passive 抓取
**实测**（`_jd_verify_replay.py` / `_jd_capture_headers.py`，容器 xvfb headed + session）：
- 容器 xvfb-headed **能过 jdsz 页面反爬**（`jdsz.jd.com` 正常加载）✅
- 但裸 fetch szgateway 接口返 **`-402「不安全的请求」`** ❌
- 真 SPA 请求头带：**`user-mnp`（每请求 32-hex 签名）** + `user-mup`（ms 时间戳）+ `uuid`（每请求）+ referer=`jdsz.jd.com/szweb/view/index/home.html` + `x-requested-with:XMLHttpRequest`。
- `user-mnp` ≠ 任何简单 md5(uuid/mup/…)（试过 6 种组合全不中）→ 是 obfuscated JS 算的签名。**不 forge**。

**结论：切片2 走 passive 抓取轨（不是参数化 replay）**：
1. headed（容器 xvfb）+ session 加载商智 SPA 页 → SPA 自己带 user-mnp 发 szgateway 请求 → `page.on("response")` 抓 JSON 响应（SPA 签名，我只读，零对抗）。
2. 覆盖靠**导航**：`getMenuTree.ajax` 拿菜单树 → 逐页 visit → 抓每页 szgateway 响应。
3. 日期 = 页面默认（今日/昨日）→ 适合**日级 cron 累积**（与抖音「趋势靠 cron 日累积」同模型）；历史 backfill 受限（页面默认窗口）。
4. 抽取：响应 `header.code==0` + `body.data`（list / {list}）→ 按指标码映射 mvp_daily_metric（platform='jd' _SHOP_，jd_ 前缀命名）。口径全集走 `getDims/getModelFunc.ajax`。
5. scout 集成：现有 live_fetch 是「goto host + runner.js fetch」的 replay 模型，**不适配 passive 导航抓取**——passive 轨需要新的「导航+抓响应」executor（或独立 host headed 定时脚本喂落库桥）。这是切片2 的主要工程。

**风险/取舍**：passive 轨稳健（不 forge、不脆弱），但①只能拿页面默认日期窗口②要可靠导航 SPA 各页（菜单树驱动）③scout 现有 replay executor 要扩或旁路。**轨 B（导出按钮 xlsx）** 仍是更省事的兜底（文件下载无签名），但要逐报表点导出+解析。
