# audience-pack-diagnosis：人群包投前诊断 + 提纯 SOP

实现《和田宽人群包评估方法论》的两份说明书（`docs/audience-pack/`）：**《02 对比诊断》**（投前体检）+ **《01 提纯》**（大包收窄）。核心 tool = `diagnose_audience_pack`（确定性引擎，逻辑全在后端，skill 只编排 + 每步停等反馈）。

## 为什么要投前诊断（先跟老板对齐，别跳）
- 和田宽**出厂价已 ≥ 竞品线上零售价，打不了价格战**。投放靠"做用户喜欢的内容 → 软植入 → 深度种草 → 收割"。所以做内容/投放**之前**必须判断一个包适不适合——这群"会被内容打动"的人必须是**真需求**。
- **行业 A4 = 一个月内真买过酱油的人 = 真需求标尺**（不是提纯工具、不是模仿对象）。比对**看方向，不算总相似分**。
- **画像比对只是投前的冷启动代理**——能判断圈选合不合理、生成"先测哪些细分"的假设，但**判断不了真实投放价值**；真实价值只有 CTR/CVR/ROI/GMV 说了算。这句每次都要跟老板讲清，别让诊断卡被当成投放价值判断。

## 三个铁律（方法论主线，diagnose_audience_pack 已内建，你转述时别说反）
1. **价值维（付得起：消费力/城市/手机价位）要正向偏离 A4 高端尾部**——贴近 A4 均值是**反的**（A4 大多价格敏感，恰是和田宽最打不动的人）。
2. **需求维要重叠 A4 真需求指纹**（品类锚 TGI 1300+/兴趣锚 220–280/触点锚 300–490），重叠高 = 真需求强。
3. **身份维差异不计**（构成不同 ≠ 质量缺口）；购买行为维比 A4 软 = 种草信号（非扣分，定漏斗位）。

## Step 0：拿到候选包画像
1. 候选包画像从**巨量引擎/云图 人群分析**导出 CSV（结构 `标签类型,标签,占比,tgi`）。老板有几种给法：
   - 已 bundle 的范例：`diyu_xunwei`（地域寻味人）、`baseline_a4`（行业 A4）。
   - 新包：老板把导出的 CSV 丢进 `services/knowledge-engine/config/audience/`，告诉你文件名。
   - 直接给容器可达的绝对路径 / 原始 CSV 文本。
2. **⚠️ 老板从客户端上传 CSV 的处理（必读，否则会卡死）**：上传的文件落在
   `C:\Users\Administrator\.omni-desktop\uploads\<sid>\<uuid>.csv`，prompt 里会带它的路径。
   - **绝不 `Read` 整个 CSV**——人群包画像 ~3000 行 / 200KB，撑爆 Read token 上限（25k），
     会一段段翻、翻不完、卡死没结果（这就是之前卡住的根因）。
   - **正确做法**：用 Bash/PowerShell 把上传文件**copy 进** `services/knowledge-engine/config/audience/`，
     用附件的**原始文件名**起个干净名（如 `地域寻味人.csv`），再 `diagnose_audience_pack(candidate='地域寻味人')`
     —— 工具在容器里直接读，不进你的上下文，秒出。例：
     `Copy-Item "C:\Users\Administrator\.omni-desktop\uploads\<sid>\<uuid>.csv" "E:\agent\omni\services\knowledge-engine\config\audience\地域寻味人.csv"`
   - **若上传的就是 地域寻味人 / 行业A4**（看附件原始文件名），直接用内置 `diyu_xunwei` / `baseline_a4`，**不用 copy**。
   - 同理上传两个文件想"候选 vs 自带基准"：候选 copy 进去当 candidate，baseline 用内置 `baseline_a4`（或老板上传的 A4 也 copy 进去指定）。
3. 基准默认 `baseline_a4`（内置行业 A4 真需求标尺，静态，不用老板给）。
4. 确认清楚 `candidate` 怎么传，进 Step 1。

## Step 1：投前诊断（diagnose_audience_pack）
```
diagnose_audience_pack(candidate="diyu_xunwei")          # 纯确定性、零 token
```
- 把 `result.markdown`（投前诊断卡）给老板看，重点讲三块：
  - **三维方向**：价值维（正向偏离高端？）/ 购买行为维（比 A4 软=种草）/ 需求重叠（留住几个真需求锚）。
  - **漏斗定位**：种草型 / 即投收割型 / 价值流失·慎投——一句话讲清"投放上该怎么对待它"。
  - **内容策略定调**：跟着定位走的内容方向（**假设**，每条带"要证实需对比真实转化"）。
- 提醒老板：这是投前冷启动代理，**判断不了真实投放价值**，定调要小预算测了看 CTR/CVR/ROI 再放量。
- `ok:false` 时：`candidate_not_found` → 看返回的 `available` 内置包名 + `dropbox` 路径，让老板把 CSV 丢对地方或核对文件名。
- **停下等老板反馈**：满意进 Step 2/3；要换包/换关注点就重调。

## Step 2：提纯施工单·优先级阶梯（按需，老板说"太大了/收窄/提纯/缩一个量级"）
诊断默认已带 `with_purify_plan=True`，诊断卡里就有《提纯施工单·优先级阶梯》。老板要单独看提纯：
```
diagnose_audience_pack(candidate="X", with_purify_plan=True)
```
- **优先级阶梯（不限刀数，按漏斗定位排序，A4 不参与）**——同一刀对不同功能的包先后不同：
  - **种草型**：先非电商需求/内容刀（内容兴趣 → 广告触点 → 价值），电商刀压后。
  - **收割型**：先高客单/品类成交（即便含电商数据），内容兴趣最后。
  - **价值流失型**：先把买不起的切到死（价值刀）。
- **每刀标 ✅非电商 / ⚠电商 资格**（这是硬约束，向老板讲清）：
  - ✅非电商刀（消费力/城市/手机价位 · 抖音/头条/西瓜兴趣 · 广告触点）→ **可上非品牌广告，投放范围大**。
  - ⚠电商刀（电商品类成交 / 品牌成交 / 高客单高频）含电商成交数据 → **只能上品牌广告，不能上传非品牌广告**。
  - → **要走非品牌广告（可投范围更大）就只切 ✅非电商 的刀，电商刀跳过。**
- 每刀落到画像里**真实可勾的巨量云图标签**（`数据工厂 → 维度 → 标签`），老板照着在云图后台点。
- **用法（老板要的"一刀一刀缩"）**：按优先级**从上往下切**，每切完去云图看实际覆盖人数；**量级不满意就把缩窄后的画像重新导出，再跑一次本工具做二次提纯**。工具不预测量级（云图实际覆盖人数只有后台看得到）。
- **关键提醒**：切量会改变需求成色——**提纯之后再跑一次 Step 1 诊断**（诊断的是最终真投出去那个包，不是原始大包）。
- A4 查无此人的新开发细分 = 假设，先小预算测，转化了再放量。

## Step 3：写细 + 小白可操作（按需，老板说"写细点/给能落地的打法"）
```
diagnose_audience_pack(candidate="X", polish=True, focus="老板临时关注点")
```
- 在确定性骨架上跑 LLM 叙事层（**巨量云图 KB grounding**），把内容策略 + 提纯指引写成**完全不懂巨量云图的小白也能照着操作**的步骤。
- 骨架是 ground truth：数字/定位/施工单**不变**，LLM 只写叙事 + 内容打法（标 `[KB]`/`[行业推理]`，禁新增数值/伪因果）。
- KB 召回为空也 fail-open 回退骨架（`narrated=False`），不假装有 KB 打法。

## 通用约束（跟其他 omni skill 一致）
- **每步停下等反馈**，尤其 Step 1→2 之间（提纯前先让老板看诊断结论）。
- **带来源**：诊断数字标"画像真值"；内容打法标 `[KB]`/`[行业推理]`；A4 真需求锚标 band（品类锚 1300+ 等）。
- **说人话**，禁 AI 化套话（赋能/打通/闭环/抢占心智/极致/匠心/一站式）。
- **反幻觉**：画像里没有的标签/数字不编（引擎已硬约束）；polish 叙事若发现编造，叫停重跑或回退骨架。
- **别说反方向**：价值贴近 A4 均值是错的（要往高端偏）；A4 是真需求标尺不是模仿对象；身份维差异不扣分。
