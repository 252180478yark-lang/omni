# 短视频内容类型目录

内容类型按**观众为什么继续看**定义。家庭、单人、厨房、晚归是场景；有机、配料表、套组是选题主题，都不能单独计为内容类型。

## 候选类型池

| code | 类型 | 核心观看价值 | 最适合解决 | 典型承载方式 | 使用前提 |
|---|---|---|---|---|---|
| `STORY` | 生活微剧情 | 看一件小事最后怎样被完成 | 产品如何自然进入普通生活 | 事情发生→人物应对→生活结果 | 有一件具体事件，不靠强反转 |
| `VLOG` | 第一人称生活日记 | 看真实的一天或一顿饭 | 广告感重、缺少日常真实性 | 时间地点→连续动作→日常收尾 | 能维持真实时间和人物状态 |
| `COMEDY` | 轻喜剧反差 | 笑一下、认出自己 | 商品介绍太硬、人物太标准 | 小嘴硬、小误会、行为反差 | 笑点不来自产品神效或羞辱人物 |
| `RELATION` | 关系互动 | 看一句话如何被回应 | 家庭/朋友关系缺少具体动作 | 消息、语音、便签、当面一句话 | 不强行升华亲情，不让他人念卖点 |
| `POV` | 个人生活观点 | 认同一种选择或生活态度 | 信息多但缺少“为什么值得考虑” | 人物先给个人判断，再用生活动作支撑 | 只能代表个人，不替所有人下结论 |
| `HOWTO` | 跟做型教程 | 学到一份能照着试的做法 | 不知道产品具体怎么用 | 食材→步骤→调味节点→成品 | 用量和步骤必须现场真实；不承诺标准答案 |
| `ASMR` | 沉浸式做饭过程 | 连续观看真实动作和声音 | 观众反感口播、需要轻松观看 | 开盖、倒汁、锅声、翻炒、装盘 | 同一锅真实过程，声音与画面一致 |
| `UNBOX_PLAN` | 开箱与套组规划 | 看收到后怎么安排 | 规格多、不会放、不会开 | 完整开箱→位置/顺序→真实使用 | 仅表达这一户安排，不冒充品牌功能设计 |
| `QNA` | 评论区一问一答 | 一个疑问得到一个清楚答案 | 规格、用法、证据看不懂 | 真实问题→动作/资料回答→保留判断权 | 问题来自真实评论或批准问题池 |
| `SWITCH` | 旧瓶见底换购记录 | 看一次选择如何发生 | 现有产品能用，缺少换购理由 | 旧瓶见底→看一条标准→新瓶进入日常 | 不露竞品、不贬竞品、不做无证据对比 |
| `PROOF` | 商品证据核验 | 看主张和当前商品能否对应 | 不信任品质词和演员口播 | 主张→来源→商品对应→表达边界 | 当前瓶身/证书/材料已审核；一片一证据 |
| `ROUTINE` | 日常使用记录 | 看产品在多次普通使用中是否自然 | 单次摆拍感强 | 同一人物在两到三个真实使用时刻重复拿起/放回 | 不能伪造长期使用或空瓶结果 |
| `CHECKLIST` | 个人选品清单 | 获得一套个人判断顺序 | 不知道选调味品时先看什么 | 个人标准 1/2/3＋对应实物动作 | 每一项都有来源；不能做全行业权威标准 |

## 默认选型方法

1. 先按当前输入筛掉不成立的类型：
   - 不是套组，删 `UNBOX_PLAN`。
   - 没有真实评论或批准问题，暂不做 `QNA`。
   - 没有审核材料，删 `PROOF`，不要预留虚构字幕。
   - 没有真实旧瓶触发，不做 `SWITCH`。
2. 从剩余类型中优先选择与人群内容兴趣和生活状态匹配的类型。
3. 正式批次先覆盖至少 10 个不同 code，每个 code 至少一条。
4. 覆盖 10 种后，才给最匹配的类型追加第二条。
5. 每种类型写清独立的 `watch_value`。如果两条的观看价值相同，只是换场景或换菜品，仍算同一类型。

## 去同质化检查

以下变化**不构成新类型**：

- 家庭换成单人。
- 晚上换成周末中午。
- 炒饭换成拌面或豆腐。
- 男演员换成女演员。
- 同一剧情只换三个开头。
- 同一证据从配料表换成有机证书，但内容机制仍是 `PROOF`。

以下变化通常构成新类型：

- 从“看事情结果”的 `STORY` 改为“能照着做”的 `HOWTO`。
- 从口播问答 `QNA` 改为无口播、靠声音留人的 `ASMR`。
- 从展示开箱安排的 `UNBOX_PLAN` 改为记录真实选择过程的 `SWITCH`。
- 从个人观点 `POV` 改为需要审核材料的 `PROOF`。

## 类型不足时

不要硬凑证据或功效。优先从 `STORY / VLOG / COMEDY / RELATION / POV / HOWTO / ASMR / ROUTINE / CHECKLIST` 中补足，这些类型可以建立在真实生活和已知规格上；仍然不足时，明确列出缺失素材，而不是把场景名包装成类型名。
