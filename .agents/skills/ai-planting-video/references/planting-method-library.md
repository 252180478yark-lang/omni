# 种草方法库

## 何时读取

- `LINEAGE_REVIEW`：确认画像痛点与 SKU 事实是否足以进入种草。
- `BRIDGE_REVIEW`：提炼并审查痛点—产品动作—解除桥。
- `SCRIPT_REVIEW`：选择 M1/M2 与 M3–M9 组合并检查脚本是否忠实执行。

缺少本文件时阻断以上状态，不借用软广的生活流框架代替。

## A1/A2 到 A3

软广解决“先愿意看、先觉得与我有关”，种草继续完成“这个产品能解决我的具体麻烦，而且理由可信”。种草视频的最小因果顺序是：

```text
画像中的具体生活状态
→ 可观察的麻烦与后果
→ 当前 SKU 的可见动作
→ 可观察的结果/解除
→ 有资格的产品证据
→ 信念变化或 A3 行为
```

种草仍需可看，但完播不是 winner。北极星是投后 A3；不要用更高完播替代相信建立。

## M1/M2 × M3–M9

每条脚本选择一个相关性模块和一个论证模块：

- `M1`：问题相关性。先展示目标人群会认出的麻烦、代价或未完成任务。
- `M2`：情境相关性。先展示人群的生活时刻，让痛点自然发生。
- `M3`：可见前后对比；前后条件必须可比。
- `M4`：动作证明；产品通过真实动作产生结果。
- `M5`：产品事实解释；只用 SKU/卖点矩阵中可核验事实。
- `M6`：使用过程消疑；用步骤、剂量、时间或适用场景降低不确定性。
- `M7`：感官结果；只描述画面/声音能观察到的变化，不编口味结论。
- `M8`：角色反应；反应必须由当前动作和结果挣得，不演夸张证言。
- `M9`：信念重构；把“我以为……”转成由证据支持的“原来可以……”。

组合写作是 `M1/M2 × M3–M9`，不是把九个模块全塞进一条。首轮候选只改变痛点场景桥或一个论证模块，其他基线固定。

## 证据资格

- Portrait/KB 明确生活状态与痛点可作为人群事实；带 🧠/⚠️ 的内容只能标作冷启动假设。
- 当前 SKU 字段、adopted 卖点矩阵、已核验产品图可作为产品事实。
- 云图 CSV 只能说明实际圈到的人群构成/信号，不能创造产品功效，也不能替代 portrait 痛点证据。
- 评论只能在来源、SKU 和真实性可追溯时使用；不能改写成虚构真人证言。
- 数字、资质、检测、促销、价格、销量没有当前事实锚时一律不写。

## 选择约束

一条视频只解决一个核心痛点，用一个主要产品动作，给一个可见结果和一个主要论证。至少一个视频段同时承载 `product_action` 与 `result_relief`；其他段按声明的适用维度评分，不能要求每段重复全部信息。

## 禁止

- 禁止硬 CTA、价格/折扣、库存紧迫、伪销量。
- 禁止把产品当贴片、把卖点写成口播清单、用品牌口号代替结果。
- 禁止虚构功效、资质、测试、用户证言或因果。
- 禁止因向量分低自动拼接 unrelated 产品事实或偷偷改 prompt 后继续烧视频。
